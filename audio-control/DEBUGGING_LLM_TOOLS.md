## How the System Works

### 1. Voice → Text
```python
audio_data = self.audio_capture.record_utterance()
text = self.speech_to_text.transcribe(audio_data)
# Result: "Can you extend the second joint?"
```

### 2. Text → Tool Calls (LLM)
```python
tool_calls, explanation = self.llm_executor.process_and_explain(text)
```

This calls OpenAI with:
- **System prompt**: Detailed robot embodiment info (joints, mappings, etc.)
- **User message**: "Can you extend the second joint?"
- **Tools**: All 15 robot tools in OpenAI function calling format
- **Model**: gpt-4o-mini

The LLM should understand:
- "second joint" = shoulder
- "extend" = move upward = positive degrees
- Default amount = 45 degrees
- **Action**: Call `move_shoulder(degrees=45)`

### 3. Execute Tool Calls
```python
task_id = self.command_queue.add_task(text, tool_calls)
```

## System Prompt (What the LLM Knows)

The LLM is told:
```
You are controlling a 5-DOF robot arm.

YOUR EMBODIMENT:
1. BASE (Joint 1, ID 6) - "rotate_base"
2. SHOULDER (Joint 2, ID 5) - "move_shoulder"  ← Second joint!
3. ELBOW (Joint 3, ID 4) - "move_elbow"
4. WRIST (Joint 4, ID 3) - "move_wrist"
5. GRIPPER (Joint 5, ID 1) - "open_gripper" / "close_gripper"

NATURAL LANGUAGE MAPPING:
- "second joint" = SHOULDER
- "extend" = move outward/forward/up (positive)
- For shoulder: extend = move up = positive degrees

ACTION-FIRST PHILOSOPHY:
- ALWAYS attempt to execute commands
- Make best interpretation and act
- Only refuse if physically impossible
```

So "extend the second joint" should → `move_shoulder(degrees=45)`

## Possible Issues & Fixes

### Issue 1: Tools Not Being Sent
**Symptom**: Debug shows "Sending 0 tools to LLM"
**Fix**: RobotTools registration is broken

### Issue 2: LLM Not Generating Tool Calls
**Symptom**: Debug shows "No tool calls generated by LLM"
**Possible causes**:
- System prompt is too long/confusing
- Model doesn't understand the command
- Tools format is incorrect
- Temperature too high (0.3 should be fine)

### Issue 3: Wrong API Key / Model
**Symptom**: API error
**Fix**: Check `.env` has `OPEN_AI_KEY`

### Issue 4: Model Can't Do Function Calling
**Symptom**: Always returns text, never tool calls
**Fix**: Ensure using `gpt-4o-mini` (supports function calling)

## Alternative: Simple Rule-Based Fallback

If the LLM continues to fail, we can add a simple rule-based parser:

```python
def parse_simple_command(text: str):
    """Fallback parser for simple commands"""
    text_lower = text.lower()
    
    # Joint mapping
    joint_map = {
        "first joint": "rotate_base",
        "second joint": "move_shoulder",
        "third joint": "move_elbow",
        "fourth joint": "move_wrist",
        "fifth joint": "close_gripper",
        "base": "rotate_base",
        "shoulder": "move_shoulder",
        "elbow": "move_elbow",
        "wrist": "move_wrist",
        "gripper": "close_gripper"
    }
    
    # Find joint
    tool_name = None
    for keyword, tool in joint_map.items():
        if keyword in text_lower:
            tool_name = tool
            break
    
    if not tool_name:
        return None
    
    # Determine direction and amount
    degrees = 45  # default
    if "extend" in text_lower or "up" in text_lower or "forward" in text_lower:
        degrees = 45
    elif "retract" in text_lower or "down" in text_lower or "back" in text_lower:
        degrees = -45
    
    if "a lot" in text_lower or "big" in text_lower:
        degrees = degrees * 1.5 if degrees > 0 else degrees * 1.5
    elif "little" in text_lower or "small" in text_lower:
        degrees = degrees * 0.33 if degrees > 0 else degrees * 0.33
    
    return [{
        "name": tool_name,
        "arguments": {"degrees": int(degrees)}
    }]
```

This would guarantee "extend the second joint" → `move_shoulder(degrees=45)`
